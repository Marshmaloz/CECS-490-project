Executive Summary  
Project Overview  
Ocean Watchdogs is a drone -based ocean rescue system designed to reduce response 
time in drowning emergencies by combining aerial mobility, computer vision, and 
automated payload deployment. Drowning remains one of the leading causes of 
accidental death wo rldwide, and traditional lifeguard response is often limited by 
distance, visibility, and human availability. Ocean Watchdogs addresses these challenges 
by providing a rapid first -response platform capable of detecting swimmers in distress 
and delivering a  flotation device while maintaining continuous communication with 
operators on the ground.  
 
System Operation  
The system supports two primary modes of operation:  
CECS -490 B: Lifesavers  
Page 8 of 35 • Manual Mode with Computer Vision Assistance  
An operator pilots the drone while receiving real -time video, telemetry, and AI -
based detection feedback.  
• Fully Autonomous Mode  
The drone independently scans the environment, identifies potential swimmers in 
distress, and initiates rescue actions with minimal human intervention.  
Once a target is detected, the drone deploys a life preserver from low altitude and 
continues tracking the individual while transmitting GPS location, video, and system 
status to the ground station until human responders arrive.  
 
Technical Architecture  
Ocean Watchdogs integrates multiple subsystems into a unified aerial platform:  
• Flight Control:  Pixhawk flight controller for stabilization and navigation  
• Onboard Computing:  Raspberry Pi companion computer running OpenCV for 
computer vision  
• Imaging:  Optical camera providing real -time FPV video  
• Communication:  Dual -channel architecture using RC for flight control and Wi -Fi 
for video and telemetry  
• Power System:  High -capacity Li -Po battery distributed through ESC/PDB to 
motors and electronics  
• Payload Deployment:  Servo -based release mechanism for flotation device 
delivery  
This dual -channel communication design improves system robustness by preventing 
total loss of control in the event of a single communication failure.  
 
Key Features  
• Real -time FPV video streaming to ground station  
• AI-assisted swimmer detection  
• GPS -based tracking and telemetry feedback  
• Redundant communication links (RC + Wi -Fi) 
• Servo -controlled life preserver deployment  
• Continuous monitoring after payload release  
Together, these features enable rapid situational awareness, precise deployment, and 
sustained tracking in dynamic outdoor environments.

Block Descriptions  
 
Drone Platform  
The drone platform provides the mechanical structure and propulsion system required for 
flight. It consists of six brushless motors, ESC controllers, a Li -Po battery, and a carbon fiber 
frame. These components enable stable aerial maneuverability while carrying additional 
computing hardware and payload systems.  
 
Flight Control System  
A Pixhawk flight controller is responsible for drone stabilization, navigation, and control 
logic. The controller processes sensor data from gyroscopes, accelerometers, and GPS 
modules to maintain stable flight.  
 
Computer Vision  
A Raspberry Pi 5 will be used to tap into the Rasberry Pi 4 video streaming allowing us to 
run inferencing on the video and determine whether a person is drowning or in distress. 
The RPI 5 will have access to all telemetry  data from the Pixhawk and communicate  
wirelessly  through  the bidirectional communication  link to the Pixhawk 6C. If in auto mode, 
the RPI 5 will cha nge the flight mode to  guide  and update it with GPS waypoints towards 
the person.  
 
Long Range FPV and Telemetry System  
Two  Raspberry Pi  4B serves as the Air and Ground units allowing for 1080 30fps video 
stream directly to the ground station but also allows for bidirectional communication on 
the same pipe using Mavlink 2 communication. This allows us to receive telemetry

connection to a laptop running Q GroundControl. Allow us to update the Pixhawk wirelessly 
and send survey GPS missions.  
 
Communication System  
Ocean Watchdogs uses a dual communication architecture:  
• RC radio control for manual flight control  
• Wi -Fi communication for telemetry and video streaming  
This redundancy ensures that  the system remains operational even if one communication 
channel experiences interference.  
 
Payload Deployment System  
A servo -controlled mechanical release mechanism allows the drone to deploy a life 
preserver to swimmers in distress. The mechanism is mounted beneath the drone frame 
and can be activated remotely or automatically.  
 
Ground Station  
The ground station consists of a laptop , Raspberry Pi  4B, and a RTK GPS base antenna  
system running ground control software that receives video streams, telemetry data, and 
detection alerts.

Flight Software  
The drone flight system is controlled by a Pixhawk flight controller running the ArduPilot 
flight stack . ArduPilot provides stabilization, waypoint navigation, and manual control 
capabilities. Through this system, the drone can be operated using a radio controller or 
follow predefined waypoint missions configured through the ground control interface.  
 
The flight controller processes data from onboard sensors including the inertial 
measurement unit (IMU) and GPS module to maintain stable flight and accurate navigation 
during operation.  
 
Computer Vision Software  
The onboard Raspberry Pi 5  runs a dual -stage computer vision pipeline designed to 
perform real -time drowning detection while maintaining efficient performance on 
embedded hardware.  
 
1. Neural Network Architecture (train.py)

This snippet defines the core CNN used for drowning classification. The architecture 
consists of four convolutional layers that extract spatial features from detected persons. 
These features are progressively reduced using pooling layers before passing thr ough fully 
connected layers. Global adaptive pooling is used to compress the feature maps into a 
single classification vector that determines whether the detected individual is swimming 
normally or exhibiting drowning behavior.  
 
2. Dual -Stage Detection Pipeline (DrownDetect.py)  
 
 
Figure 16. Dual -stage drowning detection pipeline integrating YOLOv11 and a 
custom CNN classifier.  
 
The drowning detection system uses a two -stage detection pipeline. In the first stage, a 
YOLOv11 object detection model identifies human figures within the camera frame. 
Detected individuals are then passed into the custom CNN classifier, which determines 
whether the detected subject is swimming normally or showing drowning behavior.  
The software also implements additional logic to analyze scenarios where multiple people 
are detected. In these cases, the system calculates the distance between detection 
centroids. If the distance between individuals falls below a defined threshold, the system 
triggers a precautionary drowning alert to account for potential occlusion or multi -person 
distress situations.  
 
Communication Software  
Video streaming and telemetry data are transmitted using a high -performance 
communication architecture designed for low -latency feedback between the drone and the 
ground station.  
 
OpenHD Video Transmission  
The system uses OpenHD , an open -source digital video transmission system designed for 
CECS -490 B: Lifesavers  
Page 21 of 35 drone communication. OpenHD enables high -definition video streaming with extremely 
low latency by transmitting raw Wi -Fi frames using packet injection techniques, which 
bypass the overhead of traditional TCP/IP networking.  
 
5 GHz Wi -Fi Communication  
The Raspberry Pi 5 communicates using the 5 GHz Wi -Fi band (802.11ac) . Operating on 
the 5 GHz band reduces interference commonly found in the 2.4 GHz spectrum and 
provides the higher bandwidth necessary for stable video transmission and telemetry.  
 
Low -Latency Transmission  
Through optimized network configuration and reduced protocol overhead, the system 
achieves video transmission latency of approximately 100 milliseconds or less . This 
ensures that operators viewing the ground station display receive near real -time video and 
detection information.  
 
Automation Logic  
The Ocean Watchdogs system includes an automation layer that allows computer vision 
detection results to trigger system responses.  
 
Detection Event Handling  
When the CNN classifier determines that a detected subject is drowning ( isDrowning == 
True ), the software sends a serial command  to the onboard control system.  
 
System Response Integration  
This modular automation design allows detection events to trigger additional actions such 
as alert notifications, MAVLink control commands, or payload deployment. The system 
architecture allows future expansion where the drone could automatically track det ected 
individuals or deploy flotation devices in response to confirmed drowning events.

Verification  
To verify the functionality of the Ocean Watchdogs system, multiple subsystem tests were 
conducted throughout the development process. These tests included hardware integration 
testing, communication verification, flight validation, and payload mechanism t esting. Each 
subsystem was tested individually before full system integration to ensure reliable 
performance and to isolate potential faults.  
Testing Procedures  
Several testing procedures were performed to validate the operation of the drone platform 
and supporting systems.  
 
1. Flight Testing  
Multiple outdoor test flights were conducted to verify manual flight control and waypoint -
based autonomous flight modes. The drone was tested for stable takeoff, hover, directional 
movement, and landing. Autonomous waypoint missions were also executed to e nsure the CECS -490 B: Lifesavers  
Page 22 of 35 Pixhawk flight controller correctly followed programmed flight paths.  
 
2. Landing Gear Control Testing  
The landing gear control system was tested indoors using a transmitter connected to the 
drone’s receiver. A multimeter was connected to the landing gear controller output to 
verify voltage levels and ensure that correct control signals were being transmitt ed when 
the landing gear was activated.  
 
3. Motor Power and Current Testing  
Bench tests were performed to measure motor current draw at various throttle levels. The 
motors  gradually increased from low throttle to higher throttle percentages while 
monitoring current consumption. This test ensured that the power distribution system and 
electronic speed controllers could support  the required motor loads.  
 
4. Communication System Testing  
Communication between the RC transmitter and the Pixhawk flight controller was verified 
through ground tests and flight tests. These tests ensured reliable command transmission 
and proper response of the drone’s flight control system.  
 
5. Video Transmission and Computer Vision Testing  
The Raspberry Pi companion computer and onboard camera were tested to verify real -time 
video transmission between the drone and the ground station. Simulated swimmer 
scenarios were used to test the computer vision detection pipeline and confirm that the 
system could process camera input and provide detection feedback.  
 
These testing procedures ensured that each subsystem functioned correctly before 
integration into the full rescue platform.  
 
Tolerance Analysis  
One of the most critical subsystems in the Ocean Watchdogs project is the long -range video 
transmission system. This system is responsible not only for streaming live video from the 
drone to the ground station but also for transmitting telemetry data and m aintaining a 
bidirectional communication pipeline between the drone and ground station.  
Initial testing of the video transmission system was conducted at distances of 
approximately 50 feet using a 5.745 GHz frequency band. During these tests, significant 
packet loss and unstable video transmission were observed. This instability was attribute d 
to antenna mismatch and suboptimal frequency usage for the hardware being used.  
To improve system performance, the communication system was modified by replacing the 
existing antennas with Maple Leaf 3 dBi antennas tuned specifically for the 5.2 GHz – 5.3 
GHz frequency range. This frequency band aligns better with the operating charac teristics 
of the Asus USB -AC56 AC1300 Wi -Fi adapters used in the OpenHD communication system.  
After implementing this change, additional range tests were conducted. The system 
demonstrated significantly improved performance, achieving stable video transmission at 
distances approaching approximately 1 kilometer  with minimal packet loss. The improved 
antenna tuning and frequency adjustment resulted in a cleaner video feed and more 
reliable telemetry communication.  CECS -490 B: Lifesavers

This tolerance analysis demonstrated that proper antenna selection and frequency 
optimization are critical for maintaining stable long -range video transmission in the Ocean 
Watchdogs system.

Significant Challenges and Solutions  
Hardware Integration  
Integrating the flight electronics, onboard computing hardware, and payload deployment 
system presented several challenges. The drone must maintain proper weight balance and 
center of gravity in order to achieve stable flight. Careful placement of the Pixh awk flight 
controller, Raspberry Pi companion computer, communication modules, and payload 
mechanism was required to prevent instability during flight operations. Components were 
repositioned and mounted strategically within the drone frame to maintain bal ance while 
still allowing access for wiring and maintenance.  
Wiring and Power Distribution  
The drone required custom high -current wiring for the propulsion system. Custom 14-
AWG power cables  were fabricated, soldered, and insulated using heat shrink tubing to 
connect the electronic speed controllers (ESCs) through the arms of the drone frame. In 
addition, the battery connectors were replaced with AS150 and XT150 connectors  to 
support higher current loads and improve connection reliability. These upgrades ensured 
that the power system could safely handle the electrical demands of the motors and 
onboard electronics.  
Communication Interference  
Wireless communication between the RC control link and the Wi -Fi communication system 
created potential interference issues. Since the system relies on both RC signals for flight 
control and Wi -Fi for video streaming and telemetry transmission, interferenc e could 
result in packet loss or unstable communication. To address this challenge, the team 
separated communication channels and optimized antenna placement to reduce signal 
interference and improve transmission reliability.  CECS -490 B: Lifesavers  
Page 30 of 35 Real -Time Computer Vision Processing  
Running computer vision algorithms on embedded hardware presented a significant 
challenge due to limited processing resources on the Raspberry Pi. To develop a reliable 
detection system, a training dataset of approximately  5,000 images  containing people 
swimming, drowning, or present near beach environments was collected. Each image 
required proper annotations in order to train both the YOLOv11 object detection model  
and a custom convolutional neural network (CNN) . This process required significant time 
for dataset preparation, annotation, and model training before the detection system could 
operate effectively.  
Mechanical Design and 3D Modeling  
The payload deployment mechanism required several iterations of mechanical design. 
Initial CAD models developed for earlier demonstrations did not fully meet the design goals 
for payload deployment and attachment to the drone frame. As a result, the team 
redesigned several components and explored different deployment mechanisms to 
improve reliability and structural integration. Updated CAD models were developed to 
support a more secure payload mounting system and a more reliable deployment 
mechanism.

Tools and Methodologies  
A variety of engineering tools, test equipment, and software were used throughout the 
design, construction, and testing of the Ocean Watchdogs system. These tools were 
essential for verifying hardware performance, developing software, and diagnosing

Test Equipment  
 
Digital multimeters were used to measure and verify voltage levels and current draw 
across several subsystems. Measurements were taken from the main flight battery, the 
Pixhawk flight controller power inputs, the Raspberry Pi 4B power rails, and the motor 
power distribution system. These measurements helped ensure that each component was 
receiving the proper voltage and that the power system could support the current demands 
of the motors and onboard electronics.  
 
Oscilloscopes were used to monitor electrical noise and signal behavior on the system 
power rails. During early testing, the motors were found to introduce electromagnetic 
interference (EMI) on the Raspberry Pi 4B power lines and connected peripherals. To CECS -490 B: Lifesavers  
Page 33 of 35 mitigate this issue, decoupling capacitors of 470 µF and 0.1 µF were added across the 
Raspberry Pi power rails and the Wi -Fi adapter power input. These capacitors reduced 
voltage ripple and improved overall system stability during motor operation.  
 
Software Development Tools  
 
Python was used for developing the computer vision and communication software running 
on the Raspberry Pi companion computer. OpenCV libraries were used to process camera 
input and perform human detection within the video stream. Code was developed and 
tested on the Raspberry Pi environment before being integrated with the full drone system.  
 
Flight Control Software  
 
The drone flight system was configured using the ArduPilot flight stack running on the 
Pixhawk flight controller. Ground control software was used to configure flight parameters, 
upload waypoint missions, and monitor telemetry data during testing and fligh t operations.  
 
Mechanical Design Tools  
 
Computer -aided design (CAD) software was used to design mechanical components of the 
payload deployment system. These CAD models allowed the team to design and visualize 
the payload housing, clamp mechanisms, and release components before fabrication.  
 
Together, these tools and methodologies allowed the team to systematically design, test, 
and refine the Ocean Watchdogs system while identifying and resolving hardware and 
software issues throughout the development process.
